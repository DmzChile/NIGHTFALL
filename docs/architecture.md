# 코드 구조와 변경 경계

현재 구현은 싱글 플레이 Alpha 0.3.1이다. `DESIGN.txt`는 목표 기획이며, 실제 구현 범위와 알려진 한계는 `README.md`를 따른다.

| 모듈 | 책임 |
| --- | --- |
| `data.ts` | 아이템, 제작법, 몬스터, 자원과 밸런스 정의 |
| `model.ts` | 직렬화 가능한 상태, 시드 생성, 인벤토리와 제작의 원자적 변경 |
| `validation.ts` | 저장 데이터의 런타임 검증. 입력을 수정하지 않고 복제 반환 |
| `engine.ts` | 게임 명령과 고정 시간 간격 시뮬레이션 |
| `collision.ts` | 투사체 이동 구간과 충돌 구체의 최초 접촉 위치 |
| `scene.ts` | Three.js 화면, 입력, 프레임 누적 및 30Hz 엔진 호출 |
| `animation.ts` | 부드러운 보간, 시뮬레이션 이동 샘플, 종별/손 동작 포즈 |
| `rig.ts` | 관절 그룹을 사용한 도형 모델 생성과 포즈 적용 |
| `effects.ts` | 최대 80개 파편의 단일 InstancedMesh와 GPU 자원 정리 |
| `visual-events.ts` | 성공한 동작·채집·피격의 일회성 시각 이벤트 타입 |
| `grass.ts` | 시드 기반 장식 잔디, 지형 삼각형 높이, 인스턴싱과 바람 |
| `viewmodel.ts` | 손목 기준 1인칭 손/도구 모델과 화면 비율에 따른 배치 |
| `save-queue.ts` | 중복 저장 요청 병합, 실패 시 요청 묶음 종료 |
| `storage.ts` | IndexedDB 잠금, 세대 비교, 원자적 스냅샷, 복구, 백업 파일 |
| `progression.ts` | 재료 발견·제작법 해금, 기존 월드의 제작 접근 유지 |
| `regions.ts` | 지역별 몬스터 종·Tier·위험 표시 |
| `app.tsx` | React 메뉴, HUD, 월드 관리, 시설/인벤토리 화면 |

## 시뮬레이션 순서

`Engine.step()`은 일시정지/사망/종료 상태를 먼저 확인하고 시간과 tick을 진행한다. 이후 시간/밤 스폰 → 플레이어 → 시설 → 낚시 → 지역 스폰 → 적 → 투사체 → 드랍 정리와 자동 저장 순으로 처리한다. 플레이어가 사망하면 다음 처리 단계로 넘어가지 않는다. 시뮬레이션은 렌더링 프레임이나 실제 날짜에 의존하지 않는다. 알림 만료와 저장 시각 표시는 실제 시계를 사용한다.

투사체는 한 tick에서 통과한 구간의 충돌 후보 중 가장 이른 접촉을 선택한다. 벽과 문이 같은 검색에 참여하며, 엔티티 배열 순서가 명중 대상을 결정하지 않는다. 폭발 범위 피해는 아직 거리 기준이며 지형/벽 가림은 후속 구현이다.

## 렌더러와 애니메이션

엔진은 성공한 명령 또는 양수 피해에만 `onVisual`을 전달한다. 실패한 채집, 화살/마력 부족, 재사용 대기 중에는 성공 연출을 시작하지 않는다. 시각 콜백의 오류는 재료 소비·피해·전리품 처리를 중단하지 않는다. 외부 에셋이나 애니메이션 의존성은 추가하지 않았다.

렌더러가 `visualTime`, 손 동작 시작 시각, 관절, 파편, 피격 반응과 처치 잔상을 소유한다. `State`에는 Three.js 객체와 연출 상태를 추가하지 않는다. 공격 준비/회복 포즈는 적의 기존 상태와 타이머에서 계산한다. 이동 속도는 바뀐 시뮬레이션 시각의 좌표로만 계산하므로 한 tick에서 여러 프레임을 그려도 발 동작이 끊기지 않는다. 위치와 방향은 지수 보간하며 8m를 넘는 이동은 순간 이동으로 표시한다.

연출 시간과 파편 수명은 게임이 정지하면 함께 멈춘다. 채집/피격 파편은 월드 RNG를 사용하지 않는다. 처치 잔상은 0.45초, 최대 12개를 표시하며 즉시 조준 루트에서 분리한다. 파편도 별도 루트에 있어 타격/상호작용 대상을 가리지 않는다. 조준 계산 전에 카메라와 관절 모델의 행렬을 갱신한다. 월드 전환 시 콜백과 임시 모델을 분리하고 종료 시 캐시/파편/지형/조명 도형의 GPU 자원을 해제한다.

잔디는 월드 시드·셀 좌표·포기 번호를 해시해 만들고 월드 RNG와 저장 데이터를 수정하지 않는다. 실제 PlaneGeometry의 삼각형 높이를 사용하고, 시설/바위/나무의 공간 셀을 검색해 식생을 제외한다. 최대 6,000포기를 한 메시로 그리며 시야 주변의 셀이 달라질 때만 인스턴스 버퍼를 다시 쓴다. 시설 수가 바뀌면 즉시, 나머지 주변 물체 변경은 최대 0.25초 간격으로 확인한다. 바람은 `visualTime` 유니폼을 사용하고 먼 잔디는 셰이더에서 축소한다. 잔디는 조준 루트에 넣지 않는다.

손/도구 도형은 손목 원점을 중심으로 만들며 카메라에 붙은 부모 그룹으로 배치한다. 시야각과 화면 비율에서 화면 오른쪽 아래 위치를 계산해 넓은 화면에서도 일정한 위치를 유지한다. 휘두르기는 손목 회전과 짧은 이동으로 표현하며 카메라/공격 판정을 수정하지 않는다.

## 저장 계약

1. 엔진의 저장 요청을 큐에 넣는다. 실행 중 요청은 병합하고, 진행 중 변경을 다음 저장에 반영한다.
2. `SaveManager.save()`가 상태를 복제하고 다음 세대의 체크섬을 계산한다.
3. 한 IndexedDB 트랜잭션에서 잠금 소유자/임대/기대 세대를 확인하고 월드 목록과 스냅샷을 함께 기록한다.
4. 트랜잭션 완료 후 실행 상태의 세대를 갱신하고 최근 3개 스냅샷을 보존한다.
5. 실패하면 큐의 자동 연속 재시도를 멈추고 엔진의 변경 표시를 유지한다. 이후 명시적/자동 저장 요청으로 다시 시도한다.

복구는 최신 세대부터 체크섬, 런타임 스키마, 월드 ID와 레코드 세대를 검사한다. 이전 정상 세대를 복구할 때 다음 저장의 비교 기준은 월드 목록의 최신 세대이다. 모든 후보가 실패하면 잠금을 해제하고 원본 기록을 보존한다. 검증은 예약 재료와 제작법/시설 일치, 전리품 수량과 콘텐츠 ID, 투사체 타입 등을 확인한다. 체크섬은 파일 변형 탐지용이며 보안 서명이나 게임 부정행위 방지 장치가 아니다.

## 추가 상태와 호환성

저장 format/content/generator 버전은 1을 유지하고 새 필드를 추가했다. 검증 후 `ensureProgression()`이 기존 저장본의 누락된 발견 기록·해금 목록·지역 스폰 시각을 초기화한다. 이전 월드는 기존 제작법을 유지한다. 신규 월드는 손 제작/돌 도구만 공개한다. 새 상태를 만들 때는 `createWorld()`를 사용한다.

낚시는 아이템 UID, 시작 위치, 남은 시뮬레이션 시간, 사전 판정된 성공 여부를 저장한다. 복사 가져오기는 낚싯대 UID도 새 인스턴스로 연결한다. 낚싯대 보관 시 즉시 작업을 취소하여 메뉴에서 바로 저장해도 참조가 남지 않는다. 몬스터의 지속 피해 잔여 시간/누적 초와 손상된 장비 전리품 상태도 저장한다. 지역 적은 `night=0`으로 밤 계획과 구분하고 지역별 재생성 시각은 월드에 둔다.

## 후속 확장 순서

- 브라우저 실제 플레이 검증: 포인터 잠금, 메뉴 전환, 재접속, 가져오기/복구, 기기별 FPS.
- 메뉴/HUD/시설 UI를 별도 React 컴포넌트로 분리하고 엔진의 UI 구독 경계를 명시한다.
- 대규모 월드를 도입할 때 공간 검색, 청크별 저장 및 버전 이관을 함께 설계한다.
- 이 기반 위에서 동굴, 보스 패턴, 추가 토템과 장비 슬롯을 추가한다.

`tests/run.test.ts`는 `game.test.ts`, `features.test.ts`, `animation.test.ts`, `grass.test.ts`를 함께 실행한다. 테스트는 런타임 게임 변경, 저장 계약, 검증, 충돌, 포즈, 시각 이벤트와 잔디의 회귀를 검사한다. Chromium 소프트웨어 WebGL에서도 화면과 명령을 확인했지만 실제 기기의 성능과 브라우저 WebMCP 지원을 대신 검증하지 않는다.
