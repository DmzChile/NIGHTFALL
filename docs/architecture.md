## 시뮬레이션 순서

`Engine.step()`은 일시정지/사망/종료 상태를 먼저 확인하고 시간과 tick을 진행한다. 이후 시간/밤 스폰 → 플레이어 → 시설 → 낚시 → 지역 스폰 → 적 → 투사체 → 드랍 정리와 자동 저장 순으로 처리한다. 플레이어가 사망하면 다음 처리 단계로 넘어가지 않는다. 시뮬레이션은 렌더링 프레임이나 실제 날짜에 의존하지 않는다. 알림 만료와 저장 시각 표시는 실제 시계를 사용한다.

투사체는 한 tick에서 통과한 구간의 충돌 후보 중 가장 이른 접촉을 선택한다. 벽과 문이 같은 검색에 참여하며, 엔티티 배열 순서가 명중 대상을 결정하지 않는다. 폭발 범위 피해는 아직 거리 기준이며 지형/벽 가림은 후속 구현이다.

## 렌더러와 애니메이션

엔진은 성공한 명령 또는 양수 피해에만 `onVisual`을 전달한다. 실패한 채집, 화살/마력 부족, 재사용 대기 중에는 성공 연출을 시작하지 않는다. 시각 콜백의 오류는 재료 소비·피해·전리품 처리를 중단하지 않는다. 외부 에셋이나 애니메이션 의존성은 추가하지 않았다.

렌더러가 `visualTime`, 손 동작 시작 시각, 관절, 파편, 피격 반응과 처치 잔상을 소유한다. `State`에는 Three.js 객체와 연출 상태를 추가하지 않는다. 공격 준비/회복 포즈는 적의 기존 상태와 타이머에서 계산한다. 이동 속도는 바뀐 시뮬레이션 시각의 좌표로만 계산하므로 한 tick에서 여러 프레임을 그려도 발 동작이 끊기지 않는다. 위치와 방향은 지수 보간하며 8m를 넘는 이동은 순간 이동으로 표시한다.

연출 시간과 파편 수명은 게임이 정지하면 함께 멈춘다. 채집/피격 파편은 월드 RNG를 사용하지 않는다. 처치 잔상은 0.45초, 최대 12개를 표시하며 즉시 조준 루트에서 분리한다. 파편도 별도 루트에 있어 타격/상호작용 대상을 가리지 않는다. 조준 계산 전에 카메라와 관절 모델의 행렬을 갱신한다. 월드 전환 시 콜백과 임시 모델을 분리하고 종료 시 캐시/파편/지형/조명 도형의 GPU 자원을 해제한다.

## 지형과 높이

`terrainVertexHeight()`는 시작 평지, 숲 언덕, 북쪽 능선, 화산 봉우리와 정상 분지, 유적 고원 및 해안 경사를 계산한다. `scene.ts`는 1,100m PlaneGeometry의 200×200칸 정점에 이 높이를 적용하고 지역/고도별 색상을 준다. 80,000개 삼각형의 한 지면 메시를 사용한다. 장식 잔디 메시와 바람 셰이더는 제거했으며 섬유 채집 자원은 유지한다.

`terrainHeight()`는 해당 칸의 두 삼각형을 그대로 보간한다. `model.height()`는 이 함수를 노출하여 카메라·자원·적·시설·드랍·투사체 판정이 같은 지면을 사용하게 한다. 점프 Y는 지면에 대한 상대 높이다. `terrainSlope()`는 X/Z 높이 변화로 경사 크기를 구해 시설 배치의 0.4 제한에 사용한다. 원거리 적은 지면과 점프를 포함한 플레이어 중심을 향해 3차원 발사 방향을 계산한다.

지형은 시드마다 달라지지 않으며 월드 생성의 자원/적 난수와 분리되어 있다. 경사별 이동 속도, 낙하 피해, 굴착과 지형 편집은 후속 구현이다.

손/도구 도형은 손목 원점을 중심으로 만들며 카메라에 붙은 부모 그룹으로 배치한다. 시야각과 화면 비율에서 화면 오른쪽 아래 위치를 계산해 넓은 화면에서도 일정한 위치를 유지한다. 휘두르기는 손목 회전과 짧은 이동으로 표현하며 카메라/공격 판정을 수정하지 않는다.

## 나무와 하늘

`NodeState.tree`는 크기(small/normal/large/world), 수종(pine/oak/birch/maple), autumn 플래그와 색조 변형(0/1)을 담는다. `nodeDefinition()`이 기본 자원 정의와 크기를 결합하여 채집·재생·HUD에 같은 내구도/보상/도구 조건을 제공한다. 도끼 단계는 나무 타격량 3/5/7/9에 연결하며 다른 광물의 기존 채집량은 유지한다. `nodeRadius()`는 줄기 크기를 이동 및 시설 배치에 반영한다.

`ensureForest()`는 별도 시드 난수를 사용하여 추가 숲을 만든다. 12m 격자의 숲/습지/초원 확률은 0.86/0.3/0.24이고 외곽·시작 공급 구역·급경사를 제외한다. 주변 자원·시설·플레이어·전리품과 세계수 공터를 비우며 후보 검색에 공간 셀을 사용한다. 기존 자원과 게임 RNG를 다시 생성하지 않는다. 세계수는 세 후보 영역에서 공간과 경사를 확인해 최대 3그루 배치한다.

`TreeField`는 줄기·가지·수관을 정점 색상의 단일 외형 도형으로 합치고, 크기/수종/단풍/색조/목재 종류별 InstancedMesh에 배치한다. 공유 도형을 캐시하고 인스턴스 용량은 필요한 만큼 2의 거듭제곱으로 늘린다. 플레이어 주변 150m의 나무를 8m 셀 이동 또는 활성 자원 상태 변경 시 재배치한다. 인스턴스 ID는 원래 노드에 연결되므로 채집/고갈/재생 시 대상이 바뀌지 않는다. 채집 흔들림만 임시 행렬로 표시하며 연출 시간 정지와 자원 해제를 따른다.

`SkyBackdrop`은 월드와 별도의 장면/카메라를 사용한다. 하늘 카메라는 원점에서 월드 카메라의 회전·시야각·화면 비율만 따른다. 천체는 게임 시간의 궤도에서 계산하며 안개·월드 좌표·조준 루트에서 분리한다. 하늘을 먼저 렌더한 뒤 깊이 버퍼를 비우고 월드를 그리므로 지형과 수관이 천체를 가린다. 렌더러 autoClear 설정은 성공/실패 후 원래 값으로 돌린다. 주광/야광 방향도 현재 카메라 위치를 기준으로 계산해 섬 가장자리에서 방향이 틀어지지 않는다.

## 적 식별과 안개/구름

적 식별은 수평 거리로 판정한다. 미발견 적은 공격/소환/이동을 하지 않으며, 발견 뒤에는 기본 식별 반경+12m를 추적 경계로 사용한다. 경계 밖에서 3초 지나면 공격 준비를 취소하고 대기로 돌아간다. 직접 피해와 상태 효과는 즉시 반응시키지만 지속 피해는 이탈 타이머를 초기화하지 않는다. 밤 계획 일반 적은 기존 생성 범위에서 습격하도록 46m, 지역/도전/소환 적은 종별 22~42m, 보스는 기존 전투 이탈과 같은 60m다. 130m 밖에서도 이탈 타이머와 소환물/보스 정리를 처리하여 추적이 영구히 남지 않게 한다. 미발견 적의 모델은 플레이어를 향해 회전하지 않는다. 시야 가림과 안개에 따른 AI 반경 변경은 후속 작업이다.

`CloudLayer`는 15개 군집/75개 도형을 한 인스턴스 묶음으로 하늘 장면에 추가한다. 도형은 천체보다 가까운 상부 반구에 있으며 하늘의 깊이 판정으로 태양/달을 가린다. 월드 렌더 전에 깊이를 비우는 기존 순서로 언덕·수관이 구름을 가린다. 게임 시간에서 이동/색을 재현하고 같은 시각의 중복 프레임에서는 인스턴스 갱신을 생략한다. 월드 좌표/조준 루트/RNG와 분리하며 종료 시 인스턴스 버퍼·도형·재질을 해제한다. 거리 안개는 낮/밤·새벽·습지·고도를 반영하고 가까운 전투 시야를 유지한다. 별도의 실시간 시계나 날씨 저장 데이터는 없다.

## 저장 계약

1. 엔진의 저장 요청을 큐에 넣는다. 실행 중 요청은 병합하고, 진행 중 변경을 다음 저장에 반영한다.
2. `SaveManager.save()`가 상태를 복제하고 다음 세대의 체크섬을 계산한다.
3. 한 IndexedDB 트랜잭션에서 잠금 소유자/임대/기대 세대를 확인하고 월드 목록과 스냅샷을 함께 기록한다.
4. 트랜잭션 완료 후 실행 상태의 세대를 갱신하고 최근 3개 스냅샷을 보존한다.
5. 실패하면 큐의 자동 연속 재시도를 멈추고 엔진의 변경 표시를 유지한다. 이후 명시적/자동 저장 요청으로 다시 시도한다.

복구는 최신 세대부터 체크섬, 런타임 스키마, 월드 ID와 레코드 세대를 검사한다. 이전 정상 세대를 복구할 때 다음 저장의 비교 기준은 월드 목록의 최신 세대이다. 모든 후보가 실패하면 잠금을 해제하고 원본 기록을 보존한다. 검증은 예약 재료와 제작법/시설 일치, 전리품 수량과 콘텐츠 ID, 투사체 타입 등을 확인한다. 체크섬은 파일 변형 탐지용이며 보안 서명이나 게임 부정행위 방지 장치가 아니다.

획득 세션 식별자를 저장 요청 시작 시 캡처하고 체크섬 완료 뒤 및 쓰기 트랜잭션에서 다시 확인한다. 해제 뒤 같은 월드를 다시 획득해도 이전 요청은 취소한다. 기존 세대의 월드 목록이 삭제됐으면 재생성하지 않는다. 이전 획득의 heartbeat 실패도 현재 엔진에 전달하지 않는다. 엔진 종료는 자신이 등록한 잠금 콜백만 해제한다. 권한 상실 뒤의 시뮬레이션 재개를 막고 파일 백업/명시적인 저장 없는 종료를 제공한다.

`hurt()`는 실제 피해가 처리됐는지를 반환한다. 거미와 마법 투사체의 상태이상은 그 결과와 생존 여부를 확인한 뒤 적용한다. 사망 시 회복을 제거하고 해당 tick의 후속 작업을 멈춘다. 회피는 수평 이동 구간을 기존 구체 충돌 함수로 검사한다. 노을은 하늘과 안개 색의 연속성을 유지하도록 보간한다. 상세 수정과 회귀 검사는 [코드 점검 기록](code-audit.md)을 따른다.

## 추가 상태와 호환성

저장 format/content/generator 버전은 1을 유지하고 새 필드를 추가했다. 지형은 `terrainVersion=2`를 사용한다. 체크섬과 스키마를 검증하고 복제한 뒤 `migrateTerrain()`이 필드가 없거나 1인 이전 저장본을 한 번 이관한다. X/Z 좌표, 상대 점프 높이, 인벤토리/제작 예약, UID, 세대, RNG는 유지한다. 절대 Y를 저장한 투사체에는 새 지면과 이전 높이 함수의 차이를 더한다. 2인 저장본에 재적용하지 않으며 다음 정상 저장에 새 버전이 포함된다. 엔진 생성에서도 직접 전달된 이전 상태를 이관한다. 지원하지 않는 지형 버전은 거부한다.

검증 후 `ensureProgression()`이 기존 저장본의 누락된 발견 기록·해금 목록·지역 스폰 시각을 초기화한다. 이전 월드는 기존 제작법을 유지한다. 신규 월드는 손 제작/돌 도구만 공개한다. 새 상태를 만들 때는 `createWorld()`를 사용한다.

숲은 `forestVersion=1`을 사용한다. 검증 후 `ensureForest()`가 기존 나무의 누락된 외형을 결정하고 이전 나무의 내구도(일반 6/단단한 목재 7)에 대한 남은 비율을 새 최대값에 적용한다. 고갈된 나무는 HP 0과 재생 시각을 유지한다. 숲을 한 번 추가한 뒤 버전을 기록하여 다시 불러와도 중복 생성하지 않는다. 최신 메타데이터는 나무 단계/수종/단풍/색조와 내구도 범위를 검증한다. 스냅샷·파일 백업·IndexedDB 이름과 format/content/generator 버전은 유지한다.

낚시는 아이템 UID, 시작 위치, 남은 시뮬레이션 시간, 사전 판정된 성공 여부를 저장한다. 복사 가져오기는 낚싯대 UID도 새 인스턴스로 연결한다. 낚싯대 보관 시 즉시 작업을 취소하여 메뉴에서 바로 저장해도 참조가 남지 않는다. 몬스터의 지속 피해 잔여 시간/누적 초와 손상된 장비 전리품 상태도 저장한다. 지역 적은 `night=0`으로 밤 계획과 구분하고 지역별 재생성 시각은 월드에 둔다.

## 후속 확장 순서

`ensureAwareness()`는 `alerted`/`lostFor`가 없는 이전 적·밤 계획에 추적 중/이탈 0초를 적용한다. 기존 공격 단계와 남은 준비/회복 시간, 전리품, ID, RNG를 유지하고 복제 검증 뒤 초기화한다. 새로 생성한 적은 미발견/이탈 0초다. 두 필드는 백업과 IndexedDB 스냅샷에서 검증하며 이탈 잔여 시간이 재접속으로 초기화되지 않는다. 안개/구름은 저장된 `time`에서 계산한다. 저장 format/content/generator 버전과 IndexedDB 이름은 변경하지 않는다.

- 브라우저 실제 플레이 검증: 포인터 잠금, 메뉴 전환, 재접속, 가져오기/복구, 기기별 FPS.
- 메뉴와 시설 UI를 추가로 분리하고 엔진의 UI 구독 경계를 명시한다.
- 대규모 월드를 도입할 때 공간 검색, 청크별 저장 및 버전 이관을 함께 설계한다.
- 이 기반 위에서 동굴, 보스 패턴, 추가 토템과 장비 슬롯을 추가한다.

`tests/run.test.ts`는 게임·저장·기능·애니메이션·지형·나무·식별/대기·코드 점검·조명과 `sandbox.test.ts`를 함께 실행한다. 134개 테스트는 런타임 게임 변경, 저장 계약, 검증, 충돌, 포즈, 시각 이벤트, 지형 높이, 나무 상태/채집/인스턴스 조준, 하늘 렌더 순서, 저장 이관, 크리에이티브 비용·비행·철거·명령어와 시간대별 조명/그림자의 회귀를 검사한다. 이전 Chromium 소프트웨어 WebGL 검증과 별도로 Alpha 0.53의 브라우저에서는 실제 공용 React 화면과 엔진의 입력·명령 결과를 확인했다. 이번 브라우저는 WebGL을 지원하지 않아 전체 3D 플레이와 실제 기기의 성능은 검증하지 않았다.

## Alpha 0.52 렌더링

`SceneLighting`은 태양/달의 고도로 직사광 색과 세기를 결정하고 그림자 지도 하나를 재사용한다. `configure()`는 품질 변경 시 기존 그림자 자원을 해제하고 제한된 투영 범위를 설정한다. `update()`는 플레이어 주변 범위를 조명 좌표의 texel에 맞춰 이동시키며, 시간/위치/장면에 변화가 없는 일시정지 프레임에서는 그림자를 다시 생성하지 않는다. 지형·나무·시설·생물은 그림자를 드리우고 받으며, 손/도구/방패는 제외한다. 점광원은 그림자를 사용하지 않는다.

`SkyBackdrop`의 배경 구면은 지평선 색과 천정 색을 보간하고 태양 방향의 따뜻한 산란을 표현한다. `WaterSurface`는 `MeshStandardMaterial`의 표면 법선만 바꿔 움직이는 조명 하이라이트를 만든다. 물리적 지형과 수면 높이는 유지한다. 구름·물결은 월드 `time`에서 재구성하므로 저장 필드나 월드 난수를 추가하지 않는다. 품질은 별도 브라우저 기기 설정이며 저장 접근 권한과 독립적으로 바꿀 수 있다.

태양은 카메라 회전을 따르는 원반으로, 크림색 중심·따뜻한 가장자리·부드러운 경계를 셰이더에서 계산한다. 광륜은 두 지수 감쇠를 합성하고 additive blending으로 하늘을 밝힌다. 광륜 뒤에 태양 원반을 그리며 깊이 판정은 유지하여 앞쪽 구름이 둘 다 가린다. 태양 고도로 광륜 크기와 지평선 부근의 사라짐을 조절하고 배경 구면의 약한 산란과 연결한다. 추가 렌더 패스와 화면 후처리는 없다.

## 메뉴와 배낭

`InventoryView`와 `StackGrid`는 `State`/`Stack`과 `ITEMS`에서 표시 데이터를 읽고 선택/등록/사용/수리 콜백을 호출한다. 명령과 아이템 소비는 기존 엔진을 사용한다. 선택한 묶음이 없어지면 선택 슬롯 또는 첫 소지품으로 상세 표시가 돌아간다. 공간은 `capacity()`의 칸 수, 방어력은 착용 UID와 파손 상태를 반영한다. 가방은 착용 명령 대신 휴대 시 적용되는 공간 확장을 설명한다.

기존 Radix Progress를 재사용하여 내구도/활력 정보를 접근성 값과 함께 표시하고, 카드에는 선택 상태와 착용/슬롯 상태를 구분한다. 사용 대기는 엔진의 음식 2초/물약 15초/붕대 피격 후 5초 조건을 표시한다. 게임 시간이 멈춰 있는 메뉴에서는 대기도 멈춘다. 수리 표시량은 최대 내구도로 제한한다. 반응형 스타일은 좁은 창에서 목록과 상세를 세로로 배치하고 스크롤로 접근하게 한다.

월드 목록 읽기는 렌더러 초기화에서 독립시켰다. 메뉴를 연 동안 `scene.ts`의 입력 리스너가 Tab/Space의 기본 동작을 막지 않아 대화상자의 포커스 이동과 버튼 실행을 유지한다. 플레이 중에는 기존 입력 차단을 유지한다. 저장/월드 스키마와 시뮬레이션 규칙은 바뀌지 않는다.

## Alpha 0.53 크리에이티브와 명령어

후속 Alpha 0.54 HUD 변경은 이 모드·명령어·저장 계약을 그대로 사용한다.

`State.gameMode`는 생존/크리에이티브를 나타내며 기존 `mode`의 일반/영구 사망 정책과 독립적이다. 런타임 검증 후 복제본에 누락된 `gameMode='survival'`과 `player.flying=false`를 채운다. 원본 백업과 저장 버전은 바꾸지 않는다. 최신 스키마는 모드 값을 검사하고 생존에서 비행 중인 상태를 거부한다. 모드와 비행은 스냅샷·백업에, 모드는 월드 목록 메타데이터에 저장한다.

`Engine.creative`를 통해 피해·허기·스태미나·장비 소모·아이템 소비·제작 요구 조건·자연 적 발생을 분기한다. 크리에이티브 제작은 `addItem()`의 전량 수용 검사 후 즉시 완료하고 진행 중인 기존 생존 작업은 유지한다. 가방 용량, 아이템 UID, 건축의 경사·충돌 및 저장 접근 검사는 공통으로 적용한다. 모드 전환은 난이도·사망 정책·인벤토리를 보존하고 비행/수직 속도와 밤 계획을 정리한다. 생존 복귀 시 현재 밤의 계획을 다시 생성하며 종료된 월드는 전환하지 않는다.

비행은 저장된 상대 Y에서 현재 절대 고도를 계산한 뒤 수평 이동의 새 지면 높이를 빼서 상대 Y를 갱신한다. 따라서 언덕을 지나도 고도가 지면을 따라 튀지 않는다. Space/Ctrl로 상승/하강하며 지면 기준 0~120m와 섬 경계를 적용한다. 비행 해제 후에는 기존 중력을 사용한다. 철거는 5m 안의 자원과 아이템 정의가 있는 시설만 허용하고, 시설 파괴의 기존 보관품·예약 재료 회수 경로를 재사용한다.

`commands.ts`는 256자 이하의 문자열을 명령과 인수로 분리한다. 따옴표 이름과 상대 좌표를 지원하며 허용된 11개 명령만 처리한다. 유한 좌표·정수 수량·아이템/종 ID·종별 등급과 소환 상한을 먼저 검사한다. `eval`이나 임의 코드 실행은 없다. 상태 변경은 `canModify`로 생존 상태와 저장 접근을 확인하고 원자적 지급·참조 정리·기존 저장 큐를 사용한다. 시간 명령은 현재 날짜 안의 시각만 바꾸고 자원 재생·시설 작업/작물·소비 대기·전리품 만료 등 절대 시각을 같은 차이만큼 옮겨 남은 시간을 보존한다.

`Engine.commandHistory` 40개와 `commandLog` 30개는 UI를 닫았다 열어도 유지하지만 직렬화 상태에는 포함하지 않는다. `CommandConsole`은 자동 완성·이전 입력·사용법과 성공/실패 응답을 표시하며 사용법 클릭은 실행하지 않고 입력만 채운다. `scene.ts`는 입력창·선택창·편집 영역에서 이동/퀵슬롯 키를 처리하지 않는다. 게임 플레이의 /는 포인터 잠금을 풀고 콘솔로 일시정지한다. 크리에이티브 목록과 콘솔은 컨테이너 너비와 rem 단위에 맞춰 큰 글씨에서 열 수를 줄인다.

## Alpha 0.54 HUD와 조명

`GameHud`는 엔진 상태를 읽어 날짜·방향·지역·저장·활력·상태이상·퀵슬롯·목표를 표시한다. 슬롯 변경은 `App`의 기존 선택 콜백으로 전달하며 새 저장 필드나 입력 리스너를 추가하지 않는다. 아이템/수량과 선택 상태는 접근성 이름 및 `aria-pressed`에, 내구도는 선택한 아이템의 텍스트에 표시하며 활력은 기존 Radix Progress를 사용한다. UI 재배치는 `app/game-hud.css`의 컨테이너 쿼리와 rem 단위로 처리한다. 큰 글씨에서도 상단을 한 행에 둘 수 있는 최소 너비와 하단 세 영역을 나란히 둘 수 있는 너비를 별도로 계산한다. 높이가 부족한 큰 글씨 화면에서는 세 활력 바를 가로로 모으고 상호작용 안내를 조준점 위에 둔다.

`lightingState()`는 태양 고도에서 낮의 반사광 비중을 계산하고 `golden` 구간에서 하늘/지면 반사광에 따뜻한 색을 섞는다. 밤의 주변광 하한과 차가운 달빛을 유지하며 단일 주광의 그림자 강도·필터 반경을 낮/밤에 맞춘다. `SceneLighting.update()`는 이 값을 기존 조명과 그림자 유니폼에 적용한다. 그림자 지도 해상도·범위, texel 단위 중심 안정화, 일시정지 시 갱신 생략과 품질별 자원 해제는 그대로 사용한다. 후처리 패스와 광원 수는 늘리지 않는다.

시간대 경계의 직사광/주변광 색 연속성, 낮과 밤의 그림자 차이, 시간 명령 후 1024px 그림자 지도 예산 유지, 일시정지·품질 전환을 회귀 검사한다. HUD의 시각 검증은 실제 공용 컴포넌트와 엔진을 연결한 임시 화면에서 수행하며 단색 검증 배경과 3D 환경 검증을 구분한다.
