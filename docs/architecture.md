# 코드 구조와 변경 경계

현재 구현은 싱글 플레이 Alpha 0.5이다. `DESIGN.txt`는 목표 기획이며, 실제 구현 범위와 알려진 한계는 `README.md`를 따른다.

| 모듈 | 책임 |
| --- | --- |
| `data.ts` | 아이템, 제작법, 몬스터, 자원과 밸런스 정의 |
| `model.ts` | 직렬화 가능한 상태, 시드 생성, 인벤토리와 제작의 원자적 변경 |
| `validation.ts` | 저장 데이터의 런타임 검증. 입력을 수정하지 않고 복제 반환 |
| `engine.ts` | 게임 명령과 고정 시간 간격 시뮬레이션 |
| `collision.ts` | 투사체 이동 구간과 충돌 구체의 최초 접촉 위치 |

| `visual-events.ts` | 성공한 동작·채집·피격의 일회성 시각 이벤트 타입 |

| `storage.ts` | IndexedDB 잠금, 세대 비교, 원자적 스냅샷, 복구, 백업 파일 |
| `progression.ts` | 재료 발견·제작법 해금, 기존 월드의 제작 접근 유지 |

## 시뮬레이션 순서

`Engine.step()`은 일시정지/사망/종료 상태를 먼저 확인하고 시간과 tick을 진행한다. 이후 시간/밤 스폰 → 플레이어 → 시설 → 낚시 → 지역 스폰 → 적 → 투사체 → 드랍 정리와 자동 저장 순으로 처리한다. 플레이어가 사망하면 다음 처리 단계로 넘어가지 않는다. 시뮬레이션은 렌더링 프레임이나 실제 날짜에 의존하지 않는다. 알림 만료와 저장 시각 표시는 실제 시계를 사용한다.

투사체는 한 tick에서 통과한 구간의 충돌 후보 중 가장 이른 접촉을 선택한다. 벽과 문이 같은 검색에 참여하며, 엔티티 배열 순서가 명중 대상을 결정하지 않는다. 폭발 범위 피해는 아직 거리 기준이며 지형/벽 가림은 후속 구현이다.

## 렌더러와 애니메이션

엔진은 성공한 명령 또는 양수 피해에만 `onVisual`을 전달한다. 실패한 채집, 화살/마력 부족, 재사용 대기 중에는 성공 연출을 시작하지 않는다. 시각 콜백의 오류는 재료 소비·피해·전리품 처리를 중단하지 않는다. 외부 에셋이나 애니메이션 의존성은 추가하지 않았다.

렌더러가 `visualTime`, 손 동작 시작 시각, 관절, 파편, 피격 반응과 처치 잔상을 소유한다. `State`에는 Three.js 객체와 연출 상태를 추가하지 않는다. 공격 준비/회복 포즈는 적의 기존 상태와 타이머에서 계산한다. 이동 속도는 바뀐 시뮬레이션 시각의 좌표로만 계산하므로 한 tick에서 여러 프레임을 그려도 발 동작이 끊기지 않는다. 위치와 방향은 지수 보간하며 8m를 넘는 이동은 순간 이동으로 표시한다.

연출 시간과 파편 수명은 게임이 정지하면 함께 멈춘다. 채집/피격 파편은 월드 RNG를 사용하지 않는다. 처치 잔상은 0.45초, 최대 12개를 표시하며 즉시 조준 루트에서 분리한다. 파편도 별도 루트에 있어 타격/상호작용 대상을 가리지 않는다. 조준 계산 전에 카메라와 관절 모델의 행렬을 갱신한다. 월드 전환 시 콜백과 임시 모델을 분리하고 종료 시 캐시/파편/지형/조명 도형의 GPU 자원을 해제한다.

## 지형과 높이

`terrainVertexHeight()`는 시작 평지, 숲 언덕, 북쪽 능선, 화산 봉우리와 정상 분지, 유적 고원 및 해안 경사를 계산한다. `scene.ts`는 1,100m PlaneGeometry의 200×200칸 정점에 이 높이를 적용하고 지역/고도별 색상을 준다. 80,000개 삼각형의 한 지면 메시를 사용한다. 장식 잔디 메시와 바람 셰이더는 제거했으며 섬유 채집 자원은 유지한다.

`terrainHeight()`는 해당 칸의 두 삼각형을 그대로 보간한다. `model.height()`는 이 함수를 노출하여 카메라·자원·적·시설·드랍·투사체 판정이 같은 지면을 사용하게 한다. 점프 Y는 지면에 대한 상대 높이다. `terrainSlope()`는 X/Z 높이 변화로 경사 크기를 구해 시설 배치의 0.4 제한에 사용한다. 원거리 적은 지면과 점프를 포함한 플레이어 중심을 향해 3차원 발사 방향을 계산한다.

지형은 시드마다 달라지지 않으며 월드 생성의 자원/적 난수와 분리되어 있다. 경사별 이동 속도, 낙하 피해, 굴착과 지형 편집은 후속 구현이다.

손/도구 도형은 손목 원점을 중심으로 만들며 카메라에 붙은 부모 그룹으로 배치한다. 시야각과 화면 비율에서 화면 오른쪽 아래 위치를 계산해 넓은 화면에서도 일정한 위치를 유지한다. 휘두르기는 손목 회전과 짧은 이동으로 표현하며 카메라/공격 판정을 수정하지 않는다.

## 나무와 하늘

`NodeState.tree`는 크기(small/normal/large/world), 수종(pine/oak/birch/maple), autumn 플래그와 색조 변형(0/1)을 담는다. `nodeDefinition()`이 기본 자원 정의와 크기를 결합하여 채집·재생·HUD에 같은 내구도/보상/도구 조건을 제공한다. 도끼 단계는 나무 타격량 3/5/7/9에 연결하며 다른 광물의 기존 채집량은 유지한다. `nodeRadius()`는 줄기 크기를 이동 및 시설 배치에 반영한다.

`ensureForest()`는 별도 시드 난수를 사용하여 추가 숲을 만든다. 12m 격자의 숲/습지/초원 확률은 0.86/0.3/0.24이고 외곽·시작 공급 구역·급경사를 제외한다. 주변 자원·시설·플레이어·전리품과 세계수 공터를 비우며 후보 검색에 공간 셀을 사용한다. 기존 자원과 게임 RNG를 다시 생성하지 않는다. 세계수는 세 후보 영역에서 공간과 경사를 확인해 최대 3그루 배치한다.

`TreeField`는 줄기·가지·수관을 정점 색상의 단일 외형 도형으로 합치고, 크기/수종/단풍/색조/목재 종류별 InstancedMesh에 배치한다. 공유 도형을 캐시하고 인스턴스 용량은 필요한 만큼 2의 거듭제곱으로 늘린다. 플레이어 주변 150m의 나무를 8m 셀 이동 또는 활성 자원 상태 변경 시 재배치한다. 인스턴스 ID는 원래 노드에 연결되므로 채집/고갈/재생 시 대상이 바뀌지 않는다. 채집 흔들림만 임시 행렬로 표시하며 연출 시간 정지와 자원 해제를 따른다.

`SkyBackdrop`은 월드와 별도의 장면/카메라를 사용한다. 하늘 카메라는 원점에서 월드 카메라의 회전·시야각·화면 비율만 따른다. 천체는 게임 시간의 궤도에서 계산하며 안개·월드 좌표·조준 루트에서 분리한다. 하늘을 먼저 렌더한 뒤 깊이 버퍼를 비우고 월드를 그리므로 지형과 수관이 천체를 가린다. 렌더러 autoClear 설정은 성공/실패 후 원래 값으로 돌린다. 주광/야광 방향도 현재 카메라 위치를 기준으로 계산해 섬 가장자리에서 방향이 틀어지지 않는다.

## 저장 계약

1. 엔진의 저장 요청을 큐에 넣는다. 실행 중 요청은 병합하고, 진행 중 변경을 다음 저장에 반영한다.
2. `SaveManager.save()`가 상태를 복제하고 다음 세대의 체크섬을 계산한다.
3. 한 IndexedDB 트랜잭션에서 잠금 소유자/임대/기대 세대를 확인하고 월드 목록과 스냅샷을 함께 기록한다.
4. 트랜잭션 완료 후 실행 상태의 세대를 갱신하고 최근 3개 스냅샷을 보존한다.
5. 실패하면 큐의 자동 연속 재시도를 멈추고 엔진의 변경 표시를 유지한다. 이후 명시적/자동 저장 요청으로 다시 시도한다.

복구는 최신 세대부터 체크섬, 런타임 스키마, 월드 ID와 레코드 세대를 검사한다. 이전 정상 세대를 복구할 때 다음 저장의 비교 기준은 월드 목록의 최신 세대이다. 모든 후보가 실패하면 잠금을 해제하고 원본 기록을 보존한다. 검증은 예약 재료와 제작법/시설 일치, 전리품 수량과 콘텐츠 ID, 투사체 타입 등을 확인한다. 체크섬은 파일 변형 탐지용이며 보안 서명이나 게임 부정행위 방지 장치가 아니다.

## 추가 상태와 호환성

저장 format/content/generator 버전은 1을 유지하고 새 필드를 추가했다. 지형은 `terrainVersion=2`를 사용한다. 체크섬과 스키마를 검증하고 복제한 뒤 `migrateTerrain()`이 필드가 없거나 1인 이전 저장본을 한 번 이관한다. X/Z 좌표, 상대 점프 높이, 인벤토리/제작 예약, UID, 세대, RNG는 유지한다. 절대 Y를 저장한 투사체에는 새 지면과 이전 높이 함수의 차이를 더한다. 2인 저장본에 재적용하지 않으며 다음 정상 저장에 새 버전이 포함된다. 엔진 생성에서도 직접 전달된 이전 상태를 이관한다. 지원하지 않는 지형 버전은 거부한다.

검증 후 `ensureProgression()`이 기존 저장본의 누락된 발견 기록·해금 목록·지역 스폰 시각을 초기화한다. 이전 월드는 기존 제작법을 유지한다. 신규 월드는 손 제작/돌 도구만 공개한다. 새 상태를 만들 때는 `createWorld()`를 사용한다.

숲은 `forestVersion=1`을 사용한다. 검증 후 `ensureForest()`가 기존 나무의 누락된 외형을 결정하고 이전 나무의 내구도(일반 6/단단한 목재 7)에 대한 남은 비율을 새 최대값에 적용한다. 고갈된 나무는 HP 0과 재생 시각을 유지한다. 숲을 한 번 추가한 뒤 버전을 기록하여 다시 불러와도 중복 생성하지 않는다. 최신 메타데이터는 나무 단계/수종/단풍/색조와 내구도 범위를 검증한다. 스냅샷·파일 백업·IndexedDB 이름과 format/content/generator 버전은 유지한다.

낚시는 아이템 UID, 시작 위치, 남은 시뮬레이션 시간, 사전 판정된 성공 여부를 저장한다. 복사 가져오기는 낚싯대 UID도 새 인스턴스로 연결한다. 낚싯대 보관 시 즉시 작업을 취소하여 메뉴에서 바로 저장해도 참조가 남지 않는다. 몬스터의 지속 피해 잔여 시간/누적 초와 손상된 장비 전리품 상태도 저장한다. 지역 적은 `night=0`으로 밤 계획과 구분하고 지역별 재생성 시각은 월드에 둔다.

## 후속 확장 순서

- 브라우저 실제 플레이 검증: 포인터 잠금, 메뉴 전환, 재접속, 가져오기/복구, 기기별 FPS.
- 메뉴/HUD/시설 UI를 별도 React 컴포넌트로 분리하고 엔진의 UI 구독 경계를 명시한다.
- 대규모 월드를 도입할 때 공간 검색, 청크별 저장 및 버전 이관을 함께 설계한다.
- 이 기반 위에서 동굴, 보스 패턴, 추가 토템과 장비 슬롯을 추가한다.

`tests/run.test.ts`는 `game.test.ts`, `features.test.ts`, `animation.test.ts`, `terrain.test.ts`, `woodland.test.ts`를 함께 실행한다. 테스트는 런타임 게임 변경, 저장 계약, 검증, 충돌, 포즈, 시각 이벤트, 지형 높이, 나무 상태/채집/인스턴스 조준, 하늘 렌더 순서와 저장 이관의 회귀를 검사한다. Chromium 소프트웨어 WebGL에서도 화면과 명령을 확인했지만 실제 기기의 성능과 브라우저 WebMCP 지원을 대신 검증하지 않는다.
